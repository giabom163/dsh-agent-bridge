# 执行路由规则：什么时候用协议桥，什么时候直跑

> 2026-10-17 立。目的只有一个：**别把简单活儿拖进桥的仪式里，也别把需要留证的活儿留在会话里。**

## 一句话判据

**不可逆 / 要留证 / 要隔离 / 要长跑 / 要人审 → 走桥；其余一律直跑。**

## 走桥（命中任一）

| 条件 | 为什么是桥 |
|---|---|
| 改生产代码且需要可回滚 | 桥给独立 worktree + `before/after` 快照 + `changes.diff`，失败不影响主工作区 |
| 交付必须带证据包 | 契约哈希、plan 哈希、执行事实、`result.json`、评审门（accept/reject）都是桥的原生产物 |
| 需要隔离或路径受限 | 多任务并行改同一仓库；或产物必须落在 `allowed_paths` 内（越界即 violations） |
| 预计 > 10 分钟 / 可能超时 | 桥有墙钟超时 + 中断确认，不占当前会话 |
| 需要第三方（模型）审查 | 审查类任务（`review --decision audit|accept`）只有桥有 |
| 跨会话、无人值守、事后追责 | 桥把每一步落盘，事后可复算 |

## 直跑（上面全不命中）

- 排查与取证：读代码、翻日志、算数字、对拍
- 改自己的配置：DSH `cordis.patch.yml`、`opencode.json`、装插件、清缓存
- 写文档/方案/交接/报告
- 单文件小改且**我能立刻验证**（HTTP 200、命令输出、与 SQL 对拍）
- 一次性脚本、实验、跑基准

## 直跑的底线（不能因为没走桥就降标准）

1. 结论必须有可复现的命令或数字对拍，不接受"进程没崩"。
2. 破坏性或不可逆操作前先备份（`*.bak-<时间戳>`），并写清回滚方式。
3. 改完必须做一次活体验证（端点返回、页面加载、命令输出）。
4. 涉及密钥/凭据的操作一律不落明文。

## 两者的边界

- 直跑**不允许**跳过验证；桥**不允许**用来逃避验证——桥只加证据，不加正确性。
- 桥的启动成本（写契约 + plan + run ≈ 十几秒到几分钟）只在上面那张表命中时才值得付。
- 拿不准就问一句，而不是默认走桥。

## 实例对照（本周真实发生）

| 做了的事 | 走哪条 | 依据 |
|---|---|---|
| 改 `adapters.py` 提示词传参 + 重建 pyz | 直跑 | 单文件、改完立刻用真实任务验证 |
| R0 静态审查（39KB 契约、要证据包、要人审） | 桥 | 要 worktree + 证据 + accept 门 |
| 给 DSH 加 keep-alive 中继并 A/B | 直跑 | 一次性实验，有数字对拍 |
| 舆情 `/api/overview-stats` + 4 张图 | 直跑 | 单仓库小改、HTTP 可验 |
| 多 Agent 批量改同一仓库 | 桥 | 需要隔离与并行 |
